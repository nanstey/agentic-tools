# README Template

For a project or package entry point. Answers: what is this, why use it, how to start.

```markdown
# <Project Name>

<One or two sentences: what it does and who it is for.>

## Install

<Commands to install or add the dependency.>

## Usage

<Minimal runnable example that shows the primary use case.>

## Configuration

<Key options, environment variables, or config files. Table when there are several.>

| Option | Default | Effect |
| --- | --- | --- |
| `<name>` | `<value>` | <what it changes> |

## Common Tasks

<Short how-to entries for frequent operations, or links to guides.>

## Links

<Pointers to deeper docs: guides, reference, contributing.>
```

## Notes

- Lead with the one-line purpose; do not bury it under badges.
- Show the shortest example that runs. Cut setup that most readers skip.
- Move anything long or advanced into a linked guide; keep the README scannable.
